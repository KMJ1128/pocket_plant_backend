# 비밀번호 재설정

앱의 비밀번호 찾기는 회원가입 인증과 별개로 다음 JSON API를 사용합니다.
로그인 토큰 없이 `/api/email/**`의 기존 접근 규칙으로 호출합니다.

| POST 경로 | JSON 본문 |
| --- | --- |
| `/api/email/password-reset/request` | `email` |
| `/api/email/password-reset/verify` | `email`, `code` |
| `/api/email/password-reset/confirm` | `email`, `code`, `newPassword` |

일반 이메일 계정만 재설정할 수 있습니다. 발송 응답은 계정 존재 여부를 공개하지 않습니다.
기존 `spring.mail.*` SMTP 설정으로 인증번호를 전송합니다. 비밀번호에는 영문·숫자·특수기호가
모두 포함되어야 하며 길이는 8~15자입니다. BCrypt로 저장하고 `authVersion`을 갱신하여
변경 전 JWT를 무효화합니다. DB 스키마 변경은 필요하지 않습니다.

인증번호는 10분 유효하며 5회 오입력 시 폐기됩니다. 재발송은 1분 뒤 가능하고
새 인증번호를 다시 확인해야 합니다. 확인과 변경 요청의 이메일·인증번호가 일치해야 하며,
변경에 성공한 인증번호는 재사용할 수 없습니다. 회원가입용 인증번호로 재설정할 수 없습니다.
인증 상태는 서버 메모리에 보관하므로 재시작하면 다시 발급받아야 합니다.
서버 여러 대를 운영할 때는 공유 저장소와 원자적 소비 처리가 필요합니다.

## 반영 및 확인

프런트는 현재 `src/api/api.js`의 AWS 주소를 사용합니다. 로컬 백엔드 수정만으로는
AWS 서버에 API가 생기지 않으므로 수정한 백엔드를 해당 서버에 배포·재시작해야 합니다.
그 뒤 최신 프런트 코드로 휴대폰 앱을 다시 읽습니다.

실제 메일·DB 확인은 테스트용 일반 계정으로 진행합니다.

1. 비밀번호 찾기에서 이메일을 입력하고 메일로 받은 인증번호를 확인합니다.
2. 새 비밀번호를 저장한 뒤 새 비밀번호로 로그인이 되는지 확인합니다.
3. 이전 비밀번호 로그인과 소비된 인증번호 재사용이 거절되는지 확인합니다.

자동 검증은 메일과 DB를 모의 처리하며 실제 메일을 보내거나 계정 비밀번호를 바꾸지 않습니다.

```powershell
.\gradlew.bat test --tests '*PasswordReset*Test' --tests '*PlantDiseaseServiceTest'
```
